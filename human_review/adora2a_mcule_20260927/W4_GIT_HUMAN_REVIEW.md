# W4 Git 真人核验说明

第四周开始，本目录承接真实组员核验。

## 一条核验怎么完成

1. 主核人建立自己的 review/w4-<name> 分支；
2. 打开 HUMAN_REVIEW_QUEUE.json 找自己的任务；
3. 亲自打开原始来源，不能只读 AI 摘要；
4. 复制 review_result.template.json 到 results/w4/；
5. 填写判定、理由、原始来源和局限；
6. 本人 Git 提交；
7. 交叉复核人再次看来源并留下复核记录；
8. 负责人检查格式后合并；
9. 合并不等于 AIDD 正式通过，正式完成数仍由受控导入决定。

## 判定

只使用 VERIFIED / CORRECTED / REJECTED。

如果证据不足以判断，不要硬填 VERIFIED；在理由中写明 UNRESOLVED，并保持任务未正式放行。

## Git 能证明什么

Git 可以证明谁提交、什么时候提交、改了什么、谁又做了复核。

Git 不能单独证明科研判定正确，也不能代替 AIDD Gate。

## AI 边界

AI 可以帮忙定位文献、解释字段和找冲突，但不能替真人写最终判定、冒用真人身份提交，也不能自动增加官方真人完成数。
